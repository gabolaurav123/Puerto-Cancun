# Mapa del catalogo: 2026-10-29

## Entrega y API

Solo se crean `catalog-map.js`, `test/catalog-map.test.js` y este documento.
Se leyeron `catalog-ui.js`, `catalog-view.js`, `inventory-contract.js`,
`inventory-metadata.js`, `catalog.css`, `seo-pages.js`, `app.js` y `server.js`
sin modificarlos. No hay registros de produccion nuevos ni consultas a ellos.

```js
const root = document.querySelector("[data-catalog-root]");
const controller = window.PccCatalogMap.mount(root); // muestra y carga
await controller.ready; // "ready", "empty", "error" o "destroyed"

window.PccCatalogMap.open(root);    // alias idempotente de mount
window.PccCatalogMap.hide(root);    // lista; conserva instancia
window.PccCatalogMap.dispose(root); // antes de reemplazar ese root
window.PccCatalogMap.dispose();     // libera todas las instancias activas
```

`mount` devuelve inmediatamente el mismo controlador para el mismo root.
El controlador ofrece `show()`/`open()`, `hide()`, `destroy()`/`dispose()` y
`ready`. Una nueva respuesta SSR requiere dispose + mount sobre el nuevo root;
no se reutiliza el JSON anterior. Un observer limpia roots retirados del DOM.
Un segundo observer ajusta dimensiones sin mover el centro. No hay listeners
globales de clic ni navegacion propios que compitan con el catalogo.

Integracion a cargo del propietario de `catalog-ui.js`: cargar este script,
sustituir `openMap(root)` por `PccCatalogMap.open(root)`, usar `hide(root)` en
`data-catalog-view="list"` y `dispose(root)` antes del reemplazo. No ejecutar
ambas implementaciones Leaflet sobre el mismo canvas. La API actualiza
`aria-pressed` en los botones existentes; el caller conserva su listener.

## SSR compatible

Acepta exactamente el markup actual:

```html
<section data-catalog-root data-catalog-map-total="5">
  <form id="catalogFilters" action="/propiedades" method="get">...</form>
  <div data-catalog-map hidden>
    <div class="catalog-map-canvas"></div>
    <p class="catalog-map-status"></p>
  </div>
  <script type="application/json" data-catalog-map-data>
    [{"id":"fixture-a","title":"Unidad de prueba","url":"/propiedades/unidad",
      "latitude":21.17,"longitude":-86.81,"approximate":true}]
  </script>
</section>
```

Tambien admite `data-catalog-map-items` como script JSON o atributo JSON del
root, y `{items: [...], total: N}`. Los campos SSR `id/title/url/latitude/longitude/
approximate` no requieren conversion. `approximate:false` significa exacta;
true o precision no declarada significa aproximada. Si se dispone de ella,
`locationPrecision` (`exact`, `approximate`, `hidden`) expresa mejor la politica.

Los items deben proceder del MISMO resultado autorizado y filtrado que la lista,
antes de paginar, sin mezclar proyectos y unidades. Para contabilizar todos los
ausentes, pasar tambien las filas publicas con coordenadas null, o proporcionar
el total numerico mediante `data-catalog-map-total`/`total`. Si el SSR omite los
ausentes y no proporciona total, el modulo informa solo sobre registros recibidos;
no deduce el total del texto localizado del contador ni inventa IDs ausentes.
Los ausentes recibidos mantienen acceso a su ficha en una lista desplegable.

## Precision y enlaces

- Se excluyen borradores/privados identificados como tales. `hidden` nunca genera
  pin, coordenadas o enlace Google. La identidad publica puede seguir en la lista.
- Aproximadas: coordenadas redondeadas a 2 decimales, siguiendo la politica de
  `publicProperty` existente; pin diferenciado y texto de precision en el popup.
  No se reutiliza un enlace Google original que pueda revelar la direccion exacta.
- Exactas: conserva coordenadas autorizadas y enlaces Google HTTPS permitidos.
  Sin enlace recibido usa Google Maps Search con las coordenadas publicas.
- No convierte null, blancos, booleanos, NaN o infinito en cero. Valida rangos
  latitud [-90,90] y longitud [-180,180]. Un 0 real sigue siendo valido.
- Deduplica solo IDs internos. Dos IDs en el mismo punto, incluso con MLS 1707,
  permanecen en el popup. Coordenadas contradictorias para un ID se omiten.
- La URL de la ficha se conserva, incluidos idiomas y parametros. Solo se aceptan
  rutas HTTP(S) del mismo origen, sin credenciales; no se generan nuevos slugs.
  Titulos se insertan con textContent, nunca como HTML.
- Esta defensa en cliente NO evita una filtracion ya enviada en el JSON. El servidor
  debe aplicar `publicProperty` antes de serializar y de evaluar bbox publicas.
  Filtrar con coordenadas privadas y luego ocultarlas tambien puede revelar zona.

Rutas revisadas, sin cambios: fichas `/propiedades/...` y `/en/properties/...`,
iframes existentes `https://www.google.com/maps?q=...&output=embed`, enlaces
`https://www.google.com/maps/search/?api=1&query=...` y `googleMapsUrl` de fichas
en `seo-pages.js`/`app.js`. Los enlaces `maps.app.goo.gl` de ubicaciones exactas
se conservan como enlaces; el modulo NO los resuelve ni afirma verificarlos.
Los endpoints existentes `/api/geocode`, `/api/geocode/suggestions` y
`/api/reverse-geocode` tampoco se llaman desde este componente.

## Clusters, area y accesibilidad

La proyeccion la calcula Leaflet. La agrupacion usa celdas de 50 px y retiene
todos los IDs, con orden determinista. Al acercar se separan celdas, no registros
que comparten coordenadas. Popup mediante Enter/Espacio, cierre Escape y retorno
del foco. Enlaces del popup resaltan la ficha mediante hover o foco; el foco de
una ficha abre su grupo sin pan automatico. Controles de 44 px, regiones con
nombre accesible, estado aria-live y lista accesible tambien en movil.

Mover o acercar NO consulta ni modifica la lista. Solo pulsar **Buscar esta area**
crea/actualiza un input `bounds=west,south,east,north` y llama `form.requestSubmit()`.
Conserva todos los demas campos, incluyendo Locations repetidas, presupuesto,
moneda, entidad, modalidad y destacados. No utiliza `form.submit()` ni evita
validacion. El handler actual del catalogo decide navegacion, abortos y pagina.
No hay recorte cliente, ampliacion de filtros, orden nuevo ni anuncios inventados.

La caja se redondea hacia afuera a 6 decimales y respeta limites geograficos.
Copias del mundo se normalizan; cajas que cruzan el antimeridiano se rechazan
en vez de ensancharlas. El contrato incorporado en paralelo ya valida `bounds`,
lo serializa e intersecta con el resto de filtros; se incluye una prueba contra
esa implementacion real. La respuesta SSR debe conservar el input bounds para
recarga/Atras y volver a suministrar los items del nuevo resultado.

## Dependencias y fallos

Se conserva Leaflet **1.9.4**, version estable de la integracion existente, con
CSS/JS de UNPKG y SRI oficial. Una promesa compartida evita cargas duplicadas;
timeout 10 s, reintento tras fallo, y cancelacion logica al desmontar. No se adopta
la version alpha. [Descarga oficial](https://leafletjs.com/download.html) y
[referencia](https://leafletjs.com/reference.html).

Tiles: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, atribucion visible y cache
normal del navegador, sin precarga masiva. Es servicio best-effort, sin SLA. No
establecer una politica de Referer que lo suprima. Para otro proveedor se pueden
establecer `data-catalog-tile-url` (HTTPS) y `data-catalog-tile-attribution` (HTML
de configuracion de confianza, no contenido del inventario). Revisar capacidad,
licencia y CSP antes de produccion. [Politica OSM](https://operations.osmfoundation.org/policies/tiles/).

La CSP debe permitir estos scripts/estilos externos, tiles y el estilo local
inyectado por el modulo; una CSP estricta necesitara nonce/hash suministrado por
el integrador. Si assets o tiles fallan, se informa del fallo y la lista permanece.
Sin coordenadas ni bbox previa no se carga Leaflet ni se coloca un pin ficticio
en el centro de Cancun. No se ha modificado ninguna cabecera/CSP del servidor.

## Servicios no implementados

**Resolver Google Maps.** No hay llamadas desde el mapa. La documentacion vigente
expone `POST https://mapstools.googleapis.com/v1:resolveMapsUrls`, no el `v1alpha`
del master, con cuerpo `{urls:[...]}`, maximo 20 URLs. Requiere proyecto con
facturacion y servicio Maps Grounding Lite/Maps Experience agent tools habilitado;
credencial de servidor en `X-Goog-Api-Key` u OAuth con scope
`https://www.googleapis.com/auth/maps-platform.mapstools`. Procesar `entities`
por indice y `failedRequests`; no tratar un exito parcial como lote verificado.
Las URLs deben identificar un lugar, no una busqueda generica. Conservar URL,
fuente/fila Excel y revision humana. El coste documentado del resolver IDs-only
es $0, pero requiere cuenta de facturacion y cuotas; no se presupone disponible.
[Guia](https://developers.google.com/maps/ai/maps-experience-agent-tools/resolution-api),
[REST v1](https://developers.google.com/maps/ai/maps-experience-agent-tools/reference/rest/v1/TopLevel/resolveMapsUrls).

Si solo se obtiene un Place ID, obtener coordenadas requiere otro paso, por
ejemplo Places API New habilitada: `GET https://places.googleapis.com/v1/places/PLACE_ID`,
credencial y `X-Goog-FieldMask: id,location`. `location` activa el SKU Essentials;
no asumir que resolver IDs incluye coordenadas o habilita republicacion de datos
en OSM. Revisar politicas de uso, almacenamiento y atribucion antes de integrar.
[Place Details](https://developers.google.com/maps/documentation/places/web-service/place-details).

**Tiempos de viaje.** Requieren Routes API habilitada (`routes.googleapis.com`),
facturacion, API key restringida de backend u OAuth, origen/destino autorizado,
modo, hora y condiciones. Endpoint REST:
`POST https://routes.googleapis.com/distanceMatrix/v2:computeRouteMatrix`.
Enviar `origins`, `destinations`, `travelMode`, `routingPreference` y, si procede,
`departureTime`. Mascara minima:
`originIndex,destinationIndex,status,condition,distanceMeters,duration`.
Comprobar errores por elemento y ROUTE_EXISTS; nunca derivar minutos desde km.
Limites documentados: 625 elementos generales, 100 en TRANSIT o
TRAFFIC_AWARE_OPTIMAL, 50 waypoints totales de address/placeId. Presupuesto,
cache/licencia, reintentos y cuotas deben aprobarse antes de activarlo.
[Configuracion](https://developers.google.com/maps/documentation/routes/get-api-key),
[metodo REST](https://developers.google.com/maps/documentation/routes/reference/rest/v2/TopLevel/computeRouteMatrix).

Estas son dependencias pendientes, no funciones simuladas. No se consultaron
credenciales ni se realizaron llamadas IA, de rutas, geocoding o resolver.

La suite base usa solo Node y los modulos existentes. La prueba Chromium es
opt-in: establecer `PCC_MAP_BROWSER=1`, hacer accesible `playwright` mediante
